## Project Overview

This project developed a **Cybersecurity Audit & Risk Assessment Plan** to evaluate an organization's security controls, identify threats and vulnerabilities, quantify risk, and develop recommended remediation actions.

The assessment examined multiple areas of organizational security, including personnel security, physical security, account and password management, sensitive-data protection, disaster recovery, security awareness, and compliance.

A quantitative risk methodology was used to evaluate identified threats based on **impact and likelihood**, allowing risks to be prioritized for remediation.

---

# Project Objectives

The primary objectives of this project were to:

1. Assess existing cybersecurity and physical security controls.
2. Identify security gaps and vulnerabilities.
3. Identify potential threats affecting organizational systems and information.
4. Evaluate the impact and likelihood of identified risks.
5. Calculate risk scores using a quantitative methodology.
6. Prioritize risks based on their assessed severity.
7. Develop security remediation recommendations.
8. Evaluate organizational preparedness for incidents and disasters.
9. Identify opportunities for improving security policies and procedures.
10. Develop a structured approach for ongoing risk management.

# 2. Control Assessment Findings

The assessment identified several areas requiring improvement.

Examples included:

* Lack of formal identification badge requirements
* Insufficient visitor access controls
* Lack of a laptop security policy
* Lack of emergency area-sealing procedures
* Lack of a formal information retention policy
* Lack of a reliable backup and archive process for critical information
* Inadequate emergency and incident communication procedures
* Lack of clearly defined communication responsibilities
* Lack of a designated spokesperson for public communications
* Insufficient internal emergency communication procedures
* Lack of regular disaster-plan testing

These findings demonstrate how a security assessment can identify gaps that may not be apparent from technical controls alone.

# 4. Risk Assessment Methodology

The project used a quantitative risk-scoring methodology based on two primary factors:

* **Impact**
* **Likelihood**

Risk was calculated using:

```text id="5sl8v4"
RISK = IMPACT × LIKELIHOOD
```

Both impact and likelihood were evaluated using a **0–5 scale**.

### Risk Classification

| **Risk Score** | **Classification** |
| -------------: | ------------------ |
|          21–30 | High               |
|          11–20 | Medium             |
|           1–10 | Low                |

This methodology provides a structured approach for comparing different threats and prioritizing security improvements.

# 6. Security Risk Remediation

The project developed recommended remediation actions based on identified risks.

Key recommendations included:

### Security Awareness

Implement regular security awareness programs to reduce risks associated with:

* Social engineering
* Human error
* Credential theft
* Phishing
* Improper information disclosure

### Secure System Configuration

Provide system administrators with training focused on secure configuration and security best practices.

### Security Policy Enforcement

Regularly communicate security policies and establish mechanisms to ensure that policies are consistently enforced.

### Security Analysis

Conduct comprehensive security reviews to identify potential gaps and overlooked vulnerabilities.

### Identity Verification

Require personnel to verify the identity of individuals before providing sensitive information over the telephone or other communication channels.

### Application Installation Controls

Restrict user privileges that allow unauthorized software installation.

### Malware Protection

Deploy and maintain antivirus and anti-malware controls with current updates.

### Multi-Factor Authentication

Implement MFA to strengthen authentication and reduce the risk associated with compromised credentials.

### Helpdesk Verification

Establish strict identity-verification procedures for helpdesk and technical-support interactions.

### Encryption

Use appropriate encryption protections for passwords and sensitive information in transit.

### Backups

Maintain regular backups to support recovery following data loss, system failure, or security incidents.

The project demonstrates a structured risk-management lifecycle:

```text id="pxe6fz"
Identify Risks
      ↓
Assess Impact & Likelihood
      ↓
Calculate Risk
      ↓
Prioritize Risks
      ↓
Develop Remediation
      ↓
Implement Controls
      ↓
Monitor & Reassess
```

Risk management should be treated as an ongoing process because organizational systems, threats, vulnerabilities, and business requirements change over time.

# Key Security Takeaways

This project demonstrates several important cybersecurity principles:

* Security assessments should evaluate people, processes, technology, and physical environments.
* Risk should be evaluated using consistent criteria.
* Impact and likelihood can be used to prioritize security risks.
* Human behavior can create significant cybersecurity exposure.
* Security policies must be implemented and enforced.
* MFA can strengthen authentication against credential-based attacks.
* Regular backups support resilience and recovery.
* Security awareness can reduce human-related security risks.
* Risk assessments should lead to actionable remediation plans.
* Security controls should be continuously monitored and reassessed.
